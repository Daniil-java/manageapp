## 0.0.1 (в работе)
[et-85] — Источники вместо сломанного Reddit-парсера, проверка поста в одно касание, автопилот
* Fix: в канал почти ничего не приходило — old.reddit.com без логина редиректит на /login (reason=lor2), HTML-парсер (PostParser) получал страницу входа и находил 0 постов, ошибка уходила только в warn-лог. Плюс баги старого конвейера: ParseRedditPostScheduleProcessor передавал id reddit_post в PostQueueService.markAsFailed (помечал FAILED случайный пост очереди), при сломанном JSON от AI падал с NPE; AI-фильтр разбирал ответ через split(" ") — при переносах строк вся пачка навсегда оставалась NEW.
* Источники (миграция 0.0.56, changeset 59): таблицы channel_content_source (тип RSS / PUBMED / REDDIT, адрес, max_items, последняя ошибка, fail_count) и channel_source_item (материалы, уникальный external_id, оценка и причина AI). Засеяно 17 источников (ленты проверены 09.10): ScienceDaily ×4, Medical Xpress ×3, The Conversation ×3, Harvard Nutrition Source, Stronger By Science, Precision Nutrition, Indicator.ru, PubMed ×3 (РКИ и метаанализы: похудение и аппетит, белок и мышцы, продукты и привычки). Сабреддиты перенесены выключенными. Первый сбор локально — 104 новых материала.
* Парсеры (components/source, интерфейс SourceFetcher, выбор по типу источника в SourceFetchService):
  * RssSourceFetcher — RSS 2.0 и Atom, даты с названиями зон (EDT), ключ дубля — ссылка (одна статья в нескольких рубриках ScienceDaily сохраняется один раз).
  * PubMedSourceFetcher — E-utilities: esearch (последние 10 дней) → efetch; абстракт по разделам, журнал, тип публикации; без абстракта — пропуск.
  * RedditSourceFetcher — официальный API (CHANNELPOSTER_REDDIT_CLIENT_ID / _SECRET), без ключей — публичная RSS; отсекает рейтинг < 20, картинки, видео, NSFW, закреплённые, короткие вопросы. Пока не используется.
  * ArticleTextExtractor — полный текст статьи по ссылке (основной блок, абзацы, 400–15 000 символов). Medical Xpress отдаёт 403 — пост пишется по анонсу из ленты.
  * SourceHttpClient — 4xx не повторяет, сетевые сбои и 5xx — до 2 попыток; describe() — короткая ошибка для админа.
* Конвейер (ContentPipeline, общий замок — ручной запуск и расписание не пересекаются, занятый шаг пропускается):
  * Сбор — SourceFetchService: дубли по external_id и материалы старше max-item-age отбрасываются; ошибка источника сохраняется (видно в /src и отчёте). Не собирает, если необработанных ≥ max-backlog.
  * AI-фильтр — SourceItemFilterService: по 40 материалов, JSON-режим, оценка 0–10 с причиной (раньше «да/нет»), от approve-score — в работу; в промпт идут заголовки недавних постов, чтобы не повторять темы. Сломанный ответ — материалы остаются NEW до следующего запуска. Устаревшие NEW/APPROVED снимаются (REJECTED «устарело»).
  * Генерация — SourceItemPostService: текст из ленты (≥ 1200 символов) → скачанная статья → анонс (≥ 300); пост + ссылка на источник + оценка AI. Не больше posts-per-run за запуск и pipeline-target постов в работе (проверка + очередь).
* Проверка в одно касание (PostReviewService, ReviewPosterUpdateHandler, команда /rev): картинка генерируется сразу, админ получает готовое превью с кнопками «В очередь / Сейчас / Короче / Картинка / Без картинки / Удалить» вместо трёх шагов (текст → картинка → публикация). Новый статус PostQueue.REVIEW.
* Генерация текста (ArticleContentGenerator): промпт понимает новость, абстракт PubMed и пост Reddit, требует честно писать про исследования на животных / наблюдательные / маленькие выборки; ответ в JSON-режиме; статья обрезается до 15 000 символов. Картинка — без какого-либо текста (DALL-E/gpt-image коверкал кириллицу).
* PostPublisher (вместо PostMessagePosterUpdateHandler.sendPostContent): фото, затем текст со ссылкой «Источник: …»; используется и для превью, и для канала. Публикация по слотам: если Telegram не принял пост — FAILED, а не SENT.
* Автопилот и обслуживание (ChannelAutopilotService, каждый час):
  * Пост с оценкой ≥ autopilot-min-score, не проверенный за autopilot-after, сам встаёт в ближайший слот, админам — уведомление.
  * Пост на проверке дольше review-ttl — статус EXPIRED: не занимает место в pipeline-target, генерация продолжается; кнопки превью и /q ID работают — можно принять позже.
  * Отчёт админам в 10:00: последний пост, очередь (до какого времени), на проверке, материалы за сутки, источники с ошибками; пустая очередь — предупреждение.
* Расписание (ChannelPosterSchedulerService, Europe/Moscow): сбор 03/09/15/21, фильтр каждый час :20, генерация каждые 2 ч :40 (08:40–22:40), автопилот + снятие :50, отчёт 10:00, публикация каждые 10 мин. Поиск свободного слота — 14 дней вместо 7 (PostQueueService.SLOT_SEARCH_DAYS).
* Команды: /src — источники со статистикой за 7 дней, /src add rss|pubmed|reddit (перед добавлением — пробный сбор), /src on|off|del ID, /src run (весь конвейер в фоне), /src report. /q — очередь и посты на проверке, /q ID — превью заново. Текст или ссылка без команды — пост из статьи (ссылка становится источником).
* Настройки — application.yaml, блок channelposter (ChannelPosterProperties), всё переопределяется переменными окружения: pipeline-target 20, posts-per-run 3, max-backlog 150, approve-score 7, autopilot-min-score 8, autopilot-after 12h (0 — выключен), max-item-age 30d, review-ttl 3d.
* Deprecated (forRemoval, причина в javadoc): старый Reddit-конвейер — PostParser, RedditPostDto, RedditPost, Subreddit, их репозитории и сервисы, SubredditPosterScheduler, RedditPostFilterPosterScheduler, ParseRedditPostScheduleProcessor (сняты с расписания), SubredditAddPosterUpdateHandler (снят @Component), Command.POSTER_SUBREDDIT. Таблицы subreddit / reddit_post не тронуты.
* Удалены: ImagePosterUpdateHandler, PostMessagePosterUpdateHandler, команды /image и /post — заменены проверкой в одно касание. Кнопки на старых сообщениях в чате с ботом не работают.
* Общее для всех ботов: TelegramBot.sendReturnedMessage — если HTML не разобрался, сообщение уходило простым текстом, но метод возвращал null; теперь возвращает реально отправленное.
