## 0.0.2 (в работе)
[et-84] — Новые вакансии доходят до пользователя: поиск по дате, несколько страниц, лимит прогона
* Fix: бот почти не присылал вакансий — поиск hh по умолчанию сортирует по релевантности, первая страница (20 вакансий) почти не менялась: за 16 ч (08–09.10) из 200 загруженных 198 уже были в БД, новых — 2. Теперь к ссылке фильтра добавляется order_by=publication_time (прежнее значение заменяется), ссылка в БД не меняется.
* HhWorkFilterScheduleProcessor: до 3 страниц поиска на фильтр (page=0..2), следующая — только если на текущей были новые вакансии. Итог прогона одной строкой: фильтров, новых вакансий.
* HhVacancyScheduleProcessor: одна вакансия HH из разных фильтров (одинаковый hhId) загружается один раз (HhVacancyService.fetchAndSaveEntities) — раньше страницу вакансии и работодателя качали на каждый фильтр. Свежие первыми (больший hhId), не больше 100 вакансий за прогон — бэклог в 600 вакансий занимал единственный поток планировщика 51 минуту, остальное ждало.
* Логи: вместо «HH API error!» со стектрейсом — hhId и причина (HTTP-код и ссылка или тип сетевой ошибки); в конце прогона — разобрано / не найдено / ошибок / осталось / секунд. Ошибка страницы поиска — ссылка и код ответа. «Duplicate vacancy id» — на DEBUG (было 200 строк за сутки), по фильтру — одна строка с итогом.
* Тесты: HhApiServiceSearchUrlTest (ссылка поиска), HhVacancyScheduleProcessorTest (группировка по hhId, порядок, NOT_FOUND на группу, обрыв после ошибок, лимит).

[et-80] — Вакансии со страниц сайта вместо API hh.ru
* Fix: шедулер вакансий падал на каждой вакансии — с апреля 2026 api.hh.ru отвечает 403 Forbidden на запросы без авторизованного приложения (доступ дают только работодателям и рекрутинговым сервисам после модерации). После 4 ошибок подряд обработка обрывалась, вакансии не загружались вообще.
* HhApiService: вакансия и работодатель парсятся Jsoup со страниц /vacancy/{id} и /employer/{id} в те же HhResponseDto / HhEmployerDto (название, опыт, занятость, ключевые навыки, описание, id и описание работодателя — по атрибутам data-qa).
* Запросы идут на hh.kz, а не hh.ru: hh.ru может не открываться без российского IP, а на hh.kz те же вакансии, id и вёрстка. Ссылки поиска из WorkFilter с hh.ru и региональных поддоменов (spb.hh.ru и т.п.) переписываются на hh.kz перед загрузкой, в БД остаются как есть; регион задаётся параметром area. Ссылки на новые вакансии сохраняются с hh.kz.
* Архивная вакансия (нет описания) или 404 — HhVacancyNotFoundException, HhVacancyScheduleProcessor ставит статус NOT_FOUND_ERROR (раньше ловил FeignException.NotFound). Такие вакансии больше не считаются ошибками и не обрывают обработку.
* Скрытый работодатель (анонимная вакансия) — описание работодателя пустое, без NPE.
* HhFeignClient помечен @Deprecated (не используется, оставлен на случай доступа к API); integrations.hh-api.url в конфиге сохранён.
